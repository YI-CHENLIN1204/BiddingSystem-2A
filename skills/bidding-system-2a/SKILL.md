# BiddingSystem-2A 專案交接 Skill

## 專案定位
- 唯一指定儲存庫：`YI-CHENLIN1204/BiddingSystem-2A`（Private；main）。
- 此 Skill 是操作規則，不是固定的最新版技術規格。**不得用 Skill 的文字取代 GitHub 最新證據。**
- 優先讀取 `docs/AI_HANDOFF.md`，再讀 `README.md`，需要時查實際程式碼與最新 commit。
- 若 GitHub 連線不可用，應明確表示無法驗證最新版，不能將記憶、舊簡報、先前對話當作最新系統現況。

## 每個新對話的啟動流程
1. 確認 GitHub 連線及儲存庫 `main` 的最新 commit。
2. 讀 `docs/AI_HANDOFF.md` 和 `README.md`，必要時看特定 Controller、Service、模型、前端頁面、測試與設定檔。
3. 用簡短文字整理：已確認版本／現行架構／已完成／未完成／目前阻塞／下一個驗證點。
4. 若交接文件和程式碼衝突，**以目前程式碼、測試與設定為準**，標出文件待修正；不自行編造實測結果。
5. 詢問或執行本次任務；避免重做已驗證工作，能一次完成一組相關改動就不要拆成大量瑣碎 commit。

## 已驗證的基線（2026-11-15 讀取 README）
- 前端：`frontend/`，Vue 3 + TypeScript + Vite SPA。
- 後端：`崴正/`，ASP.NET Core Web API、EF Core、PostgreSQL。
- 前端僅透過 HTTP `/api` 與後端互動；舊 Razor UI 已移除。
- README 記載本機前端 `127.0.0.1:5174`、後端 `127.0.0.1:5261`；實際執行仍以當前設定為準。
- 資料庫密碼與密鑰不可提交到 Git 或交接文件。

## 開發約束
- **禁止假定 Z-score、LSTM、時間加權、特定門檻、Razor 等仍在使用。** 任何演算法與功能聲稱均須先確認目前實作。
- 對需求、資料表、權限、API、單位換算與歷史回寫等變更，先找受影響的前後端和資料庫路徑，保護既有行為。
- 涉及資料庫 schema 時，說明遷移、相容性、備份與回滾方式；不可只改 Entity 便宣稱資料庫更新完成。
- 使用合成／去識別化測資，不讀出或記錄合作方原始資料、帳密及部署密鑰。
- 所有驗證回報區分：已執行且通過、已執行但失敗、未執行。不得把預期結果寫成 PASS。

## 每次修改完成後的交接更新
於同次工作中同步更新 `docs/AI_HANDOFF.md`：
1. 日期與 Git commit/branch；
2. 實際更動的檔案、功能與行為；
3. 執行的驗證指令及結果；
4. 未解問題／風險／下一步；
5. 重要設計決策及已淘汰方案。
若本次無寫入權限，提供待提交的文件差異，不宣稱已同步。
不要將交接規則理解成 GitHub 會主動把變動推送到 ChatGPT：**新對話必須重新讀 GitHub**。

## 回應方式
使用繁體中文。採具體步驟、精確檔案路徑與可驗證結果；沒有證據不要猜版本／埠號／功能狀態。
