# T00～T11 最小補件與盲測驗收

以下數量是可開始的操作下限。正式樣本數須用先導組估計變異、精確度和效力後事前登錄。正式庫的 336 個合成案一律維持合成標籤。既有 SHA 鎖定的廠房腳本不能讀取外部真實包。

| 項目 | 最少資料與來源 | 取得後的驗收與輸出 |
|---|---|---|
| T00 | 住宅 frozen CSV、原 manifest、建案表、明細、材料表、交易表各一份。要有建案與來源鍵、案別、結構、開工及資料可用日、數量／單價及原單位。 | 先以 SHA 驗證原包並比對現有可追溯快照。依 `audit_frozen_factory.py` 的契約另建住宅入口，輸出來源、重複、時間及跨切分報告。現有腳本僅允許凍結廠房。 |
| T01／T02／T04／T05／T10／T11 | 起跑下限為住宅及廠房各至少 2 個相互獨立的原始來源，各來源先取得至少 5 個具明確日期的建案。含最終決標工作表、工項、規格、工料範圍、單位、數量、單價、幣別、稅與計價口徑、核定版本與首度可用時間。每個比較案另外須有足夠較早合格參考案供 K=5／8 檢驗。 | 飛地先建立真實資料轉接與 schema 驗證後，依 `replay_factory_dictionary.py`、`replay_factory_safety.py`、`replay_factory_a1.py`、`replay_factory_equal_n.py`、`factory_material_tfidf.py`、`b1_cluster_sensitivity.py` 的相同評估契約重播。輸出逐行標準答案比對、來源／結構分層、共同可估案例、棄答、配對 CI、Top-K 與錯例。資料量不足的區塊明列棄答。 |
| T03 | 至少 2 名不同受測者作 AB／BA 先導，兩張互不重複且匹配難度的標單。每場含受測者代碼、組別、開始／結束、工時、正解標註、錯誤及返工。 | 用 `prepare_human_practice.py` 作合成演練。真人紀錄用 `analyze_human_crossover.py`，輸出配對任務時間、品質、次序及返工，不以演練產物替代。 |
| T06 | 使用上述盲測案。每案保留正常候選、疑似異常和資料不足項，由工程師先獨立標註，保留爭議與最終裁決。記錄偏差量、同原單位、規格、基準及原因。 | 依 `factory_interval_stress.py` 參考邊界欄位，另建人標對照入口。輸出含棄答的混淆矩陣、Precision／Recall／FPR、逐案錯例及人際一致性。 |
| T11 原作者一致性 | 原作者程式、依賴版本、初始化、群數和帶寬規則及可跑的基準輸出。 | 在獨立容器以同輸入和版本檢查逐案一致性。未取得時維持獨立重建標籤。 |

資料保管者以一致的別名替換案名、客戶、承包商、供應商、地址、聯絡方式與內部識別碼。保留可做來源分組的匿名來源鍵。確切日期按授權存於受控空間，外發資料可用相對日序，且不能改變先後或失真。檔名、附註、藏頁和文件中繼資料也要掃描。公開 repo 僅可放 schema、腳本、合成 fixture 與經核准的匿名摘要。

人標先盲於模型輸出，先簽定規格／單位／材料對應與異常裁決原則。依來源、系列、建案與時間封鎖切分，近重複版本整組同側。獨立保管盲測答案，先凍結樣本、預測參數、採用門檻、分母與分析程式 SHA，預測封存後才由保管者解盲。正式樣本未取得時，不合併不同實驗狀態。
