# 2A 模擬歷史展示資料管理（2026-10-15）

> **僅供開發與作品展示，不代表企業歷史真值或經人工審核的最終標單。**

## 現況與限制

使用者明確要求在目前 Supabase 開發環境加入可計算 P15／P50／P85 的模擬歷史資料。此為一次性的**展示例外**，不是正式歷史匯入方案。

批次：`DEMO_2A_20261015`

- `project_master`：8 個住宅／RC 虛構建案，以「【模擬資料 DEMO_2A_20261015】」開頭。
- `final_bid_item`：24 筆結構體工程模擬價格明細，每個建案 3 筆。
- `historical_transaction`：16 筆鋼筋／混凝土數量（每案各 1 筆），**沒有價格**。
- `source_file_name`：`DEMO_2A_20261015_SIMULATED.xlsx`（資料辨識標記，不代表曾由 Excel 實際匯入）。
- `history_approved_by`：`DEMO_ONLY_NOT_REAL_REVIEW`。

為了沿用現有模型「只讀 Approved」的邏輯，本批建案資料庫狀態是 `Approved`，**但沒有通過正常的 Draft → 人工審核 → Publish History 流程**。**絕不可**將此批次用來對真實專案估價、驗證準確率或當成已定案的企業歷史資料。

## 2026-10-15 功能驗證

已從 UI 實測：

- V1/V2 AnalysisCase 快照與 AnalysisRun 可保存及重新開啟。
- V2 數量偵錯：混凝土與鋼筋各有 8 案參考，P15/P50/P85 及「偏高」可顯示。
- V2 結構體工程價格異常：8 案參考，P15/P50/P85 及「偏高」可顯示。
- 這僅驗證**計算流程與 UI**；樣本是合成值，無法證明預測品質。

## 清理與復原

使用 `scripts/cleanup_demo_2a_20261015.sql`。它以**建案名稱前綴、來源檔名稱、審核人標記**三條件鎖定本批 8 案，使用交易依序刪除其 `historical_transaction`、`final_bid_item`、`project_master`。不影響 `analysis_case`、`analysis_bid_version`、`analysis_bid_item`、`analysis_run`。

執行 SQL 前請備份並核對；若找到的建案數不是 8，腳本會中止。清除後模型會恢復樣本不足（除非已另有真實 Approved 歷史）。已保存的 Run 結果仍是當時使用模擬參考計算的快照，**清除資料不會追溯更改舊 Run**。
